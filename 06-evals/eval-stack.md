## What "good" means

≥80% thumbs-up; regenerate rate ≤15%; edit-before-send (override) rate ≤30%; abandon rate ≤10%; median time-to-first-action ≤15 min; abstention-override rate ≤10% (weekly aggregate).

- **Active:** thumbs up/down on each Juno output; "regenerate" and "edit before send" buttons; free-text feedback when thumbs-down; PM acts on a thread where Juno withheld a ranking (abstention-override)
- **Passive:** dismiss/suppress; time-to-first-action; abandon rate (PM closes thread without acting)

## The stack

| Layer | Evaluator | What it catches | Threshold / gate |
|---|---|---|---|
| Code-based | Automated checks · cadence: Every PR (CI gate) + nightly cron · owner: CI fails the PR. Eng owns format/citation. PM owns the accuracy bar. | Format check (valid markdown table with required columns) · Citation check (each risk cites a message index that exists) · Refusal check (contracts/legal language triggers refusal) · Fail-safe check (<3 retrieved chunks → insufficient-evidence banner, no ranking produced) · Isolation check (a query scoped to one team_id never returns another team's chunks) | 100% pass on format, citation, refusal, fail-safe, and isolation checks |
| LLM-as-judge | Automated assessment on the golden set · cadence: Every PR (CI gate) + nightly cron · owner: PM owns the accuracy bar | Silent wrong outputs at the long tail — top-3 accuracy vs golden set | ≥90% golden-set accuracy (rubric-aligned) |
| Human | 06-evals/human-rubric.md · 2 graders + PM tiebreak per disagreement protocol · cadence: Weekly batch (Friday afternoon) | 50 P0 triage runs / week · Stratified across confidence buckets (high / mid / low) · 100% of hand-off cases included | ≥4.0/5 mean on Accuracy, Citation grounding, and Safety; any "1" on Citation grounding OR Safety = auto-fail |

## Golden set

- 200 anonymised P0 threads with PM-curated expected top-3 risks
- Versioned in 06-evals/golden-set/
- Refresh quarterly and after every major incident

## Release gate

**Hard gates (auto-block):**

- **0% cross-team data leakage — any retrieval that returns another team's data (a `team_id` namespace breach) blocks the launch, no matter how clean the demo looks. Verified by an adversarial cross-tenant test suite, not the happy-path demo.**
- 0% PII leakage
- Any "1" on Safety (human-eval layer)
- Any "1" on Citation grounding OR automated citation-check fail
- Fail-safe check fail: ranking produced on <3 chunks

**Soft gates (PM sign-off):**

- p99 latency >5s (target p95 ≤4s, hard cap 30s) → PM justification
- Off-brand / miscalibrated tone flags >2% → PM review (not auto-block)

**User-feedback layer (online):** cadence Per request (real-time) + weekly aggregate review; owner PM reviews weekly; on-call PM triages ≥2 thumbs-down on same intent within 24h.
